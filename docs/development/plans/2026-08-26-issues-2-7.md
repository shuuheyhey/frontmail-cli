# Issues #2–#7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement each task with strict RED/GREEN TDD and an independent review gate.

**Goal:** Fix the two confirmed pagination bugs and implement the four approved read-only CLI improvements tracked by GitHub Issues #2–#7.

**Architecture:** Keep CLI parsing and request preparation deterministic and authentication-free. Add resource capability metadata, effective configuration selection, redacted diagnostics, local output projection, and named profiles as focused types instead of scattering flag checks through `main.rs`. Each Issue remains one independently committed and reviewed task in its own worktree; dependent tasks start from their producer task's reviewed commit.

## Global Constraints

- Preserve the read-only boundary: no POST, PUT, PATCH, DELETE, upload, download, message send, or mutation path.
- Never serialize tokens, resolved token-command argv, customer values, production identifiers, or raw diagnostic response bodies.
- Existing commands and default JSON envelopes remain backward compatible unless the corresponding Issue explicitly changes their invalid-input behavior.
- Invalid CLI input must fail before configuration loading, token resolution, or an HTTP request.
- All behavior changes follow strict RED → observed expected failure → minimal GREEN → refactor.
- Update `README.md`, `CHANGELOG.md`, and the directly affected files under `docs/` for each public behavior change.
- Every task runs targeted tests plus `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets --all-features -- -D warnings`, `cargo test --locked --all-targets`, `cargo build --locked --release`, and `git diff --check`.
- Each task produces one or more Conventional Commits and does not push, merge, close Issues, or create PRs.

- [ ] **Step 1: Write failing CLI contract tests**

- [ ] **Step 2: Verify RED**

```rust

```

Keep the existing inbox default `25` and existing `u32` request fields. Do not add a post-authentication check.

- [ ] **Step 4: Verify GREEN and boundaries**

Add parser assertions that `1` and `100` succeed and `0` and `101` fail for both compact inbox and generic read commands. Run targeted tests and the global quality gate.
